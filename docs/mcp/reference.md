# admin-OS MCP reference

> Generated by `npm run mcp:reference` from the MCP manifest (`src/config/mcp-manifest.ts`) and the tool projection (`src/core/mcp/project-catalog.ts`). Do not edit it by hand: `npm test` fails while it is stale.

admin-OS serves its capability catalogue as MCP tools, through the same client as the web app: permissions, approval, validation and error codes are the screens' own (ADR 0009). Each tool is one capability the manifest exposes; a UI-only capability is never a tool.

## The server

- **Protocol.** Revision `2026-07-28`, and the 2025 era (`2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`, `2024-10-07`; latest `2025-11-25`) through the SDK's stateless fallback, on both transports.
- **Transports.** Streamable HTTP at `/api/mcp` (GET, POST and DELETE), and stdio with `npm run --silent mcp:stdio`. The preset is the deployment's `VERTICAL`.
- **Auth over HTTP.** A bearer token is required and resolves the role; no token never means a role. `MCP_TOKENS` maps tokens to roles (`<token>:<role>,...`). While it is unset on the mock adapter, the public demo tokens `demo-owner-token`, `demo-manager-token`, `demo-staff-token` apply, each with its own demo session, and the server is **read-only**: anyone holds those tokens. `MCP_READ_ONLY=true` or `false` overrides either default.
- **Auth over stdio.** One actor per process: `MCP_ROLE` (default `staff`) on its own demo session; it writes unless `MCP_READ_ONLY=true`.
- **Read-only mode.** Only the tools marked `read` below are listed and run; a write answers `access.forbidden`.
- **Visibility.** An actor is offered only the tools its role's permissions allow, sorted by name. Descriptions here name every exposed tool; a server names only the tools its actor is offered.
- **Idempotency.** A tool whose mode is `key` requires the `idempotencyKey` argument: a new UUID per operation, the same one to retry it. A host may also send `_meta["admin-os/idempotencyKey"]`. A `target-state` tool takes no key: repeating it reaches the same state.
- **Tier.** Each tool's `_meta["admin-os/riskTier"]`: 0 non-personal read, 1 personal read or self-scoped write, 2 business write, 3 irreversible, money or legal.

## Tools

Each tool's input schema is JSON Schema 2020-12, as `tools/list` sends it (without `$schema`).

### `access_me_get`

**Who am I.** Who is calling: actor id, display name, role and permissions.

- Capability: `access.me.get`, permission `read:access`, tier 1, idempotency n/a (read).
- Annotations: `readOnlyHint` true, `destructiveHint` false, `idempotentHint` true, `openWorldHint` false.

```json
{
  "type": "object",
  "properties": {},
  "additionalProperties": false
}
```

### `bookings_availability_get`

**Find free times and resources.** The start times of a business day's service window, on the slot grid, each with the active resources that are free for a stay beginning there and seat the whole party on their own. An empty list means that time is full.

- Capability: `bookings.availability.get`, permission `read:bookings`, tier 0, idempotency n/a (read).
- Annotations: `readOnlyHint` true, `destructiveHint` false, `idempotentHint` true, `openWorldHint` false.

```json
{
  "type": "object",
  "properties": {
    "businessDay": {
      "type": "string",
      "pattern": "^\\d{4}-\\d{2}-\\d{2}$"
    },
    "partySize": {
      "type": "integer",
      "minimum": 1,
      "maximum": 200
    }
  },
  "required": [
    "businessDay",
    "partySize"
  ],
  "additionalProperties": false
}
```

### `bookings_cancel`

**Cancel a booking.** Cancel a pending, awaiting_payment or confirmed booking with the reason staff will see, and release its resources. Fails with bookings.invalid_transition otherwise. Find valid ids: id with bookings_list.

- Capability: `bookings.cancel`, permission `cancel:bookings`, tier 2, idempotency target-state.
- Annotations: `readOnlyHint` false, `destructiveHint` true, `idempotentHint` true, `openWorldHint` false.

  - `id`: `bookings_list`

```json
    "id": {
      "type": "string",
      "minLength": 1,
      "maxLength": 128
    },
    "reason": {
      "type": "string",
      "minLength": 1,
      "maxLength": 500
    }
  },
  "required": [
    "id",
    "reason"
  ],
  "additionalProperties": false
}
```

### `bookings_create`

**Create a booking.** Create a confirmed booking. Send exactly one of customerId (a guest on record; create one with customers_create first) or contactName. The start must be on the slot grid inside the service window. Resources are optional; when given they must be active, free for the stay and seat the party together. Fails with bookings.not_enough_seats, bookings.resource_busy, bookings.resource_inactive, bookings.outside_window, bookings.off_grid or bookings.not_found. Find valid ids: customerId with customers_list or customers_duplicates_check; resourceIds with bookings_availability_get or resources_list.

- Capability: `bookings.create`, permission `create:bookings`, tier 2, idempotency key.
- Annotations: `readOnlyHint` false, `destructiveHint` false, `idempotentHint` true, `openWorldHint` false.
- Id hints (field: tools that list valid values):
  - `customerId`: `customers_list`, `customers_duplicates_check`
  - `resourceIds`: `bookings_availability_get`, `resources_list`

```json
{
  "type": "object",
  "properties": {
    "businessDay": {
      "type": "string",
      "pattern": "^\\d{4}-\\d{2}-\\d{2}$"
    },
    "startMin": {
      "type": "integer",
      "minimum": 0,
      "maximum": 1440
    },
    "partySize": {
      "type": "integer",
      "minimum": 1,
      "maximum": 200
    },
    "resourceIds": {
      "default": [],
      "maxItems": 10,
      "type": "array",
      "items": {
        "type": "string",
        "minLength": 1,
        "maxLength": 128
      }
    },
    "customerId": {
      "type": "string",
      "minLength": 1,
      "maxLength": 128
    },
    "contactName": {
      "type": "string",
      "minLength": 1,
      "maxLength": 120
    },
    "channel": {
      "type": "string",
      "enum": [
        "phone",
        "email",
        "web",
        "in_person",
        "whatsapp",
        "instagram",
        "facebook",
        "sms",
        "google",
        "third_party"
      ]
    },
    "guestNote": {
      "type": "string",
      "maxLength": 500
    },
    "tags": {
      "default": [],
      "maxItems": 20,
      "type": "array",
      "items": {
        "type": "string",
        "minLength": 1,
        "maxLength": 40
      }
    },
    "idempotencyKey": {
      "type": "string",
      "minLength": 1,
      "maxLength": 128,
      "description": "A new unique string (a UUID works) for each distinct operation. Retrying with the same key and the same arguments returns the first result instead of applying it twice; the same key with other arguments fails with client.idempotency_conflict."
    }
  },
  "required": [
    "businessDay",
    "startMin",
    "partySize",
    "channel",
    "idempotencyKey"
  ],
  "additionalProperties": false
}
```
